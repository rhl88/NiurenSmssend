# 短信发送 · 对外调用能力加强 实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 短信模板支持设置应用级标识（alias）供其他应用按标识调用；发送记录落库调用方应用标识（caller_app）便于排查日志。

**架构：** 方案 A 最小侵入扩展——`app_niuren_smssend_templates` 加 `alias` 列（选填、全局唯一），`app_niuren_smssend_records` 加 `caller_app` 列（调用方自报标识）；`SendService` 新增 `sendByAlias()` 入口并让 `send()` 追加可选参数，原有调用全部向后兼容。设计文档见 `doc/2026-11-05-对外调用能力加强-设计.md`。

**技术栈：** Laravel（CMSPRO v5 应用）、Blade + Layui 视图、PHPUnit（应用内 Tests/Feature，sqlite :memory:）。

**约束（必须遵守）：**
- 只允许改动 `app/Apps/NiurenSmssend/` 内文件（白名单制）
- `Install.php` **无需修改**：`runMigrations()` 用 `glob(Migrations/*.php)` 自动发现迁移、逆序回滚，新迁移放入目录即生效
- 每个任务完成后单独提交：在应用目录内 `git add <具体文件>`（禁止 `git add -A`），提交信息 `type(scope): subject` 中文格式，**禁止 push**
- 测试命令统一：`php artisan test app/Apps/NiurenSmssend/Tests`（工作目录 `e:\wwwroot\cmspro\code`）

**背景速览（给零上下文的工程师）：**
- `SmsTemplate`（模板）已有 `code` 列 = 服务商侧模板 CODE（如 `SMS_512651836`），同服务商唯一，**不是**本计划的调用标识
- `SmsRecord`（发送记录）已有 `operator_id/operator_name` = 后台操作人快照；`caller_app` 是新增的「哪个应用调的」维度
- 测试基建 `Tests/Support/NiurenSmssendSetup` 会自动执行 `Migrations/` 下全部迁移，提供 `createTemplate()` / `createRecord()` 造数方法
- 服务商 HTTP 调用在测试中用 `Http::fake()` 模拟（参考 `SendServiceTest::fakeAliyunSuccess()`）

/**
 * 校验模板标识全局唯一（跨服务商）
 *
 * @throws SmsException
 */
private function assertAliasUnique(string $alias, ?int $excludeId = null): void
{
    $query = SmsTemplate::query()->where('alias', $alias);

    if ($excludeId !== null) {
        $query->where('id', '!=', $excludeId);
    }

    if ($query->exists()) {
        throw new SmsException('模板标识已被使用');
    }
}

/**
 * 按应用级模板标识查询模板（供其他应用按标识调用）
 *
 * 停用状态不做拦截，统一由 SendService::send() 校验。
 *
 * @throws SmsException
 */
public function findByAlias(string $alias): SmsTemplate
{
    $template = SmsTemplate::query()->where('alias', trim($alias))->first();

    if (! $template) {
        throw new SmsException('短信模板不存在或已被删除');
    }

    return $template;
}
