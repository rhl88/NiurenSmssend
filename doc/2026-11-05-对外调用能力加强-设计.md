# 短信发送 · 对外调用能力加强 — 设计文档

> 日期：2026-11-05 | 应用版本：1.0.3+ | 应用 ID：niuren.smssend
> 状态：设计已获用户批准

## 一、背景与目标

短信发送应用当前仅支持后台页面发送，服务层虽可被其他应用代码级调用，但存在两个短板：

1. **调用方不可追溯**：`SendService::send()` 的 `$operator` 只记录操作人，无法区分是后台手动发送还是哪个应用发起的调用，排查日志困难。
2. **按 ID 调用脆弱**：调用方必须知道模板自增 ID，模板重建/迁移后 ID 变化会导致调用失效。

目标：

- 发送记录落库调用方应用标识，记录列表可筛选、可搜索；
- 模板支持设置**应用级模板标识**（alias），其他应用按标识调用，不依赖 ID。

## 二、已确认的决策

| 决策点 | 结论 |
|--------|------|
| 模板标识规则 | **选填，全局唯一**；留空的模板仅供后台按 ID 发送 |
| 调用方身份获取 | **调用方主动传标识**，不做自动推断 |
| 实现方案 | 方案 A：最小侵入扩展（否决 CallerContext 抽象对象与 backtrace 自动推断） |

## 三、数据库变更（2 个新迁移）

### 1. `add_alias_to_app_niuren_smssend_templates_table`

- 新增列：`alias VARCHAR(100) NULL COMMENT '应用级模板标识（供其他应用按标识调用），全局唯一'`，位于 `code` 之后
- 唯一索引：`uk_niuren_smssend_templates_alias(alias)`（MySQL 唯一索引允许多个 NULL）
- `down()`：删除索引与列

### 2. `add_caller_app_to_app_niuren_smssend_records_table`

- 新增列：`caller_app VARCHAR(100) NOT NULL DEFAULT '' COMMENT '调用方应用标识（空为后台手动发送）'`，位于 `operator_name` 之后
- 普通索引：`idx_niuren_smssend_records_caller(caller_app)`
- `down()`：删除索引与列

同步更新 `Install.php`：迁移清单加入两个新迁移，回滚逻辑按倒序回滚。

## 四、模板标识（alias）

### 校验规则（TemplateService::normalizeTemplateData）

- 选填；**留空存 NULL**（唯一索引允许多个 NULL，多个空串会冲突，故不存空串）
- 填写时：`trim` 后须匹配 `/^[A-Za-z0-9][A-Za-z0-9._-]{1,99}$/`（2–100 位，字母/数字开头，允许点、中划线、下划线），不合法报「模板标识仅支持字母、数字、点、中划线、下划线，须以字母或数字开头」
- 全局唯一校验 `assertAliasUnique()`（与 `assertCodeUnique` 同模式），冲突报「模板标识已被使用」

### 界面与接口

- 模板列表：新增「模板标识」列展示；关键字搜索范围纳入 `alias`
- 模板表单：新增「模板标识」输入框，占位提示如 `user.register.verify（选填，供其他应用按标识调用）`；编辑回显
- `TemplateService::options()` 返回值增加 `alias` 字段
- `SmsTemplate` 模型：`fillable` 加 `alias`，`toSummaryArray()` 加 `alias`

## 五、调用方记录（caller_app）

### SendService 接口变化

```php
// 原有方式保持兼容：追加第 5 个可选参数
send(int $templateId, string $mobile, array $fieldValues, array $operator = [], string $callerApp = ''): array

// 新增：按模板标识发送
sendByAlias(string $alias, string $mobile, array $fieldValues, array $operator = [], string $callerApp = ''): array
```

- `sendByAlias` 内部通过 `TemplateService::findByAlias(string $alias): SmsTemplate` 查模板（新增方法）：不存在抛「短信模板不存在或已被删除」；**模板停用校验不做重复实现，统一由 `send()` 主流程抛「该短信模板已停用，无法发送」**
- `$callerApp` 落库到 `records.caller_app`；后台页面调用不传，落空串
- `SmsRecord` 模型：`fillable` 加 `caller_app`，`toSummaryArray()` / `toDetailArray()` 加 `caller_app`

### 发送记录页

- 列表新增「调用来源」列：空串显示「后台」，否则显示标识原文
- 关键字搜索范围纳入 `caller_app`（`SmsRecord::scopeKeyword` 追加 orWhere）
- 详情弹窗展示「调用来源」字段

## 六、文档与测试

### 文档（doc/ 三份同步更新）

- 使用指南：模板表单新增「模板标识」说明；记录列表新增「调用来源」说明
- 扩展指南：Service 层调用示例改为「按标识调用 + 传调用方标识」；`SendService` / `TemplateService` 方法表补 `sendByAlias`、`findByAlias`；错误处理约定不变
- 特性清单：补充两条能力点

### 测试（Tests/Feature/）

- `TemplateServiceTest`：alias 格式校验（合法/非法）、全局唯一冲突、留空可保存、`findByAlias` 命中与未命中
- `SendServiceTest`：`sendByAlias` 成功路径与模板停用失败路径、`caller_app` 正确落库、`send()` 不传 caller 时落空串
- `RecordServiceTest`：按关键字可搜到 `caller_app`；记录数组含 `caller_app`

## 七、错误处理

沿用现有约定：业务校验失败统一抛 `SmsException`（面向用户中文提示），不新增异常类型；`caller_app` 仅做 `trim` + 长度截断（100），不做格式强校验（调用方自报，宽松接收便于排查）。

## 八、范围外（明确不做）

- 不新增对外 HTTP API / 鉴权机制
- 不做调用方自动推断（backtrace / 路由分析）
- 不广播发送结果事件（Hooks 仍为预留空实现）
- 不做调用频次统计、配额等衍生功能
